# DPES-820 end-to-end isolation and failure evidence

Scope: fake-backed evidence for DPES-820 (child of DPES-803). Every test below runs against the in-memory fakes. No cloud is contacted.

Status: **not a release-gate pass.** DPES-820 cannot pass until the DPES-871 durable-continuation report passes every required case. DPES-821 (pilot enablement) stays blocked on DPES-820. Real-resource proofs are stated gaps below, each naming its blocking ticket.

Run: `uv --project cloud run pytest cloud/tests -q`

## What this change adds

- `cloud/tests/test_isolation_e2e.py`: cross-surface credential scan. A worker writes log lines and a status message containing six credential shapes through the runner plans. The test asserts that none of them appears in the run, status, logs, or result responses, or in the run record or any stored object. It also asserts that redaction markers and non-secret text are present, so the scan cannot pass merely because lines were dropped. The launch bootstrap is not scanned: it is delivered to the worker, not to a caller or to storage.
- `cloud/tests/test_checkpoint_publish.py`: `test_a_partial_publish_is_adopted_by_a_same_id_retry_and_selects_nothing_before_it`, parametrized over each publication boundary. A partly published checkpoint fails with `checkpoint_commit_failed`, and its leftovers select nothing until a retry with the same draft commits. The retry adopts the identical components and then selects exactly its own marker. Matches protocol-v1.md item 22.
- `cloud/tests/fakes.py`: `InMemoryObjectStore.names()`, so a test can scan every object a run left behind.

No product defect was found, so no product code changed. The new tests passed on first run. The sentinel scan's regression value was checked by an in-process mutation: with model-boundary redaction disabled, both scan cases fail with `reached logs response`. The checkpoint test was not mutation-checked.

Full cloud suite on this branch: 1615 passed (baseline 1609 plus the six new cases).
